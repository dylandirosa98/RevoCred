## 3. Detailed findings

### Privacy and data handling

**Public policies and final legal configuration.** The landing page loads over HTTPS. The four tested policy/support paths return 404; no alternate privacy/terms destinations were found among its home-page links. The current web preview has no production/legal defines and is therefore not evidence of the final release's legal setup. `LegalScreen` passes configured privacy/terms values to an external launcher, and its launcher ignores a false return value. With missing preview values, reliable policy navigation is not established. Publish owner-approved pages, configure the actual destinations, and verify every action on the signed app. Reconcile the two support-email domains present on the landing page and confirm the chosen inbox is monitored; mailbox delivery was not tested.

**AI recipient mismatch.** The legal screen names OpenAI, but the live disclosure names `OpenCode Go and DeepSeek (testing)` with `deepseek-v4.1-flash`. Dynamic consent correctly identifies the actual live recipient. Either complete the planned OpenAI switch or accurately disclose the provider actually chosen for launch. Do not claim that Apple mandates OpenAI. Confirm provider retention/data-use settings and then test consent grant, decline, revoke and notice changes against the final backend.

**Consent/account isolation.** Source and passing tests cover cancel/basic/agree, notice changes, failed disclosure, stale-version rejection, account switches, revoke, chat cancellation and clearing history. The live endpoint rejects a stale notice with 409 and missing/empty input with 422; no-consent requests return `mode: basic`. These support the implemented boundary but do not prove absence of every possible data leak or native-device behavior.

**Privacy declarations.** Runner declares non-tracking, UserDefaults reason `CA92.1`, and collection categories for account, financial, content, usage and diagnostic data. Source includes optional marketing-email opt-in; the manifest includes developer advertising for email. Check final Connect answers against actual hosting logs, SMTP, AI and support practices. Signed archive aggregation and SDK manifests remain device/archive gates. No final privacy label was inspected in Connect.

### Permissions and entitlements

Inspected `Info.plist`, AppDelegate, app config and direct dependencies. The native auth scheme is `com.revocred.app`; the Runner bundle identifier is separately `com.revocred.revocredFlutter`. Source declares standard encryption and no broad camera, location, microphone or tracking prompts. There is no observed reason to introduce those permissions. Signing team/entitlements and aggregate privacy validation still require the actual archive. Verify install, callback handling, plugin behavior and first-frame rendering on supported devices.

### Monetization

No IAP or payment SDK appears in the current Flutter dependencies. Apply actions open issuer/partner websites; visible affiliate and external-site disclosures exist. The launcher handles failures. This audit found no digital-feature purchase requiring an IAP/restore implementation. Final live destinations, commercial relationships and permitted artwork/data use still need owner verification; no real credit application was submitted.

### Account and authentication

The app uses email/password, offers a guest questionnaire/report path and makes legal information available signed out. No social-login integration was found. In-app account deletion asks for the current password and confirmation. The server requires recent password authentication; deletion and export use authenticated endpoints.

A disposable **local** account passed signup, login, logout/relogin, emailed recovery/password update, wallet-containing export, deletion, old-token rejection and rejected login after deletion. Its live application/auth account was removed by the smoke script. Local signup confirmation was disabled, so this did not test confirmation email delivery. Local callback URI structure passed, but no installed app consumed it. Verify hosted SMTP, allowlisted callback/recovery URLs and hosted account lifecycle with disposable accounts on the processed build; do not infer those results from local Mailpit.

### Content, REVO and external links

**Reproduced basic-reply defect.** A public request with content `Explain what this demo app does.` and no AI-consent version returns HTTP 201 and an assistant message in `basic` mode. Its text includes `Use the supplied breakdown in cents` and `Never convert AI web/marketing prose into modeled value or alter rankings.` `Snapshot(...).Disclaimer` contains model directions and the deterministic provider appends that field as a visible note. This is an internal wording leak, not evidence of a secret or private-account leak. Split private model instructions from user copy and assert both rendered blocks and plain-text output omit internal imperatives.

**AI safety/reporting acceptance gap.** The Report action supports harmful/offensive reasons; authenticated feedback is stored against the user's assistant message. Source inspection did not establish a staffed queue, response commitment or operational handling. The final model was not exercised with safety cases, and no external-AI requests were made by this audit. Test the final configured service and establish who reviews reports. Private REVO is not an observed public user-to-user feed, so social-user blocking is not automatically prescribed here.

**External links.** Chat link parsing permits HTTPS and reports launcher failures. Card application buttons disclose the destination type and handle errors. Legal link launching lacks equivalent false-result handling. iPad PDF sharing and native browser/mail integration remain unverified on the final binary.

### UX and reviewability

Widget tests cover responsive auth, input validation, duplicate-submit guards, friendly errors, session expiry/isolation, recovery, wallet/card flows, chat, reports, Explore Rewards and PDF generation. These are automated source tests, not a new visual/browser/device journey. Increased text size, VoiceOver, network transitions, IPv6-only behavior, iPad sharing and installed account email returns still require acceptance. The release preview's missing legal values mean it should not be presented as the final distributable build.

The submission draft repeatedly promises permission per message; current behavior persists account permission until revoke or notice change. Update all listing/reviewer instructions before use. Screenshots, age rating, availability/trader fields, app record, reviewer login and current Apple membership were not verified through Connect. Seller eligibility should reflect the actual educational planning scope and sensitive data; this audit does not assert financial licensing is required or established.
